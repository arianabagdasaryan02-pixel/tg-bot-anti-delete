## Что это

Вы подключаете бота к своему аккаунту. Дальше он просто присматривает за вашими личными чатами.

Кто-то написал вам и через минуту удалил сообщение? Бот пришлёт вам копию того, что было. Переписал сообщение, пока вы не видели? Бот покажет обе версии: что было и что стало.

Работает это через [Telegram Business API](https://core.telegram.org/bots/features#business-mode): Telegram сам сообщает боту об удалении и правках, потому что вы дали боту такое разрешение в настройках аккаунта.

## Что умеет

- 🗑 **Удалённое** — пришлёт копию сообщения, которое стёрли
- ✏️ **Изменённое** — покажет, что было до правки и что стало после
- 📎 **Файлы любого размера** — фото, видео, кружочки, голосовые, гифки, стикеры, документы. Придут оригиналом, а не описанием
- 🅱️ **Форматирование на месте** — жирный, курсив, зачёркнутый, спойлер, код и ссылки останутся такими же
- 📍 **Не только текст и файлы** — геопозиция, контакт, опрос, кубик и история тоже не пропадут
- 👤 **Кто это был** — имя и кликабельный `@username`, а если его нет, то номер профиля, по которому можно открыть человека

## Чего бот у себя не держит

Важная часть, чтобы не казалось, будто ваша переписка где-то копится.

- **Файлы на диске не копятся.** Обычно бот ничего не качает — он запоминает только номер файла внутри Telegram. Копию делает в единственном случае: если Telegram отказался переслать оригинал. Такая копия живёт считаные секунды и удаляется сразу после отправки
- **Тексты живут не дольше суток.** Раз в день скрипт очистки стирает всё старое и сжимает базу
- **Никакого облака.** База — обычный файл рядом с ботом, на вашем сервере. Он никуда не уходит
- **Ваши собственные сообщения не записываются.** Бот смотрит только на то, что пишут вам

## Размер файлов: откуда лимит и почему здесь он не мешает

У ботов в Telegram есть жёсткое правило: **скачать себе файл больше 20 МБ бот не может**. Это ограничение Telegram, а не чья-то недоработка — так устроен их Bot API, см. [документацию getFile](https://core.telegram.org/bots/api#getfile).

Сначала бот честно качал файлы к себе на диск. Из-за этого всё, что крупнее 20 МБ, до пользователя не доходило, а диск постепенно забивался копиями.

Потом стало понятно, что качать вообще незачем. Файл ведь уже лежит на серверах Telegram. Чтобы переслать его вам, боту не нужно сначала тянуть его к себе — хватает ссылки на внутренний номер файла. А у пересылки по номеру ограничения на размер нет.

Так бот и работает сейчас: он не скачивает ничего, запоминает только номер, а когда сообщение удаляют — просит Telegram отдать вам оригинал напрямую. Из этого следует:

- файл приходит любого размера, хоть на гигабайт;
- на диске у бота пусто, забиваться нечему;
- лимит в 20 МБ просто не наступает, потому что скачивания нет.

Бывает, что Telegram отказывается пересылать файл в исходном виде — так случалось с некоторыми стикерами. На этот случай есть запасной ход: бот скачивает файл к себе и отправляет уже своей копией. Копия временная и удаляется сразу после отправки, так что на диске всё равно ничего не накапливается. Сработает это для файлов до 20 МБ — выше Telegram скачивать не даёт.

Минус у решения тоже есть: постоянной копии не остаётся. Если Telegram совсем перестанет отдавать файл, взять его будет неоткуда — ни переслать, ни скачать. Бот реагирует на удаление за секунды, так что случай редкий, но полностью исключить его нельзя.

## Что нужно

- Python 3.10 или новее
- Библиотека [python-telegram-bot](https://github.com/python-telegram-bot/python-telegram-bot) 21.6+ (проверено на 22.x)
- Токен бота — его выдаёт [@BotFather](https://t.me/BotFather)
- **Включённый Secretary Mode (режим секретаря)** у вашего бота. Без него Telegram не даст подключить бота к аккаунту. Раньше этот режим назывался Business Mode, так что в старых инструкциях встречается другое имя

## Установка

```bash
git clone https://github.com/arianabagdasaryan02-pixel/tg-bot-anti-delete.git
cd tg-bot-anti-delete

python -m venv venv
source venv/bin/activate  # Windows: venv\Scripts\activate

pip install -r requirements.txt
```

## Настройка

1. Сделайте свой файл с настройками из примера:

```bash
cp config.example.py config.py
```

2. Впишите в `config.py` токен и имя бота:

```python
BOT_TOKEN = "123456:ABC-..."
BOT_USERNAME = "your_bot_username"  # без символа @
```

3. Включите режим секретаря:
   - @BotFather → `/mybots` → ваш бот → `Bot Settings` → раздел `Mode Settings` → `Secretary Mode`
   - Если пропустить этот шаг, при подключении Telegram напишет «Этот бот пока не поддерживает режим секретаря»

4. Подключите бота к своему аккаунту:
   - Профиль → «Изменить» → «Автоматизация чатов»
   - Впишите имя вашего бота

## Запуск

```bash
python bot.py
```

## Где его держать включённым

> ⚠️ **Важно.** Telegram хранит пропущенные ботом события **не дольше 24 часов**. Если бот был выключен дольше суток, то удаления и правки за это время он уже не покажет — Telegram их просто не отдаст. Это тоже ограничение их стороны.

Поэтому бот должен работать постоянно. Варианты:

- **Свой компьютер** — годится, чтобы попробовать. Выключили компьютер — бот замолчал
- **VPS**, примерно от 150–500 ₽ в месяц — работает сам по себе круглосуточно, обычный выбор
- **Бесплатные хостинги** вроде Bothost или Amvera — проще в настройке, но с ограничениями по ресурсам

📖 Подробности по каждому варианту с командами — в [DEPLOYMENT.md](DEPLOYMENT.md)

## Автозапуск на сервере

В комплекте есть готовый файл `avtozapusk.service`. Он поднимает бота после перезагрузки сервера и перезапускает, если тот упал.

```bash
sudo cp avtozapusk.service /etc/systemd/system/avtozapusk.service
sudo systemctl daemon-reload
sudo systemctl enable --now avtozapusk
systemctl status avtozapusk
```

## Ежедневная очистка

`cleanup.py` стирает всё, что старше суток. Поставьте его в cron, чтобы запускался раз в день:

```bash
crontab -e
```

Добавьте строку (каждый день в 4 утра):

```
0 4 * * * /home/botuser/bot/venv/bin/python /home/botuser/bot/cleanup.py >> /home/botuser/bot/cleanup.log 2>&1
```

Срок хранения задаётся в начале `cleanup.py` константой `DAYS_TO_KEEP`. По умолчанию 1 — то есть дольше суток ничего не лежит.

## Что где лежит

```
.
├── bot.py              # Сам бот
├── cleanup.py          # Ежедневная очистка (запускается по cron)
├── config.example.py   # Образец настроек
├── requirements.txt    # Зависимости
├── avtozapusk.service  # Автозапуск на сервере
├── DEPLOYMENT.md       # Подробная инструкция по развёртыванию
├── demo.png            # Скриншот для этой страницы
│
│   # ниже — то, что появляется на месте и в репозиторий не попадает:
├── config.py           # Ваш токен, создаёте сами
├── messages.db         # Реестр замеченных сообщений
├── venv/               # Виртуальное окружение с зависимостями
└── media_archive/      # Временная папка, обычно отсутствует
```

Про три последних пункта подробнее.

**`messages.db`** — обычный файл базы рядом с ботом. Там лежат тексты и номера
файлов внутри Telegram, по одной строке на сообщение. Скрипт очистки стирает
всё, что старше суток.

**`venv/`** — отдельная папка с библиотеками для этого бота. Нужна, чтобы
зависимости не ставились на всю систему и не ссорились с другими программами.
Создаётся один раз при установке, трогать её не нужно.

**`media_archive/`** — не архив, хотя название такое. Это временная папка на
один файл. Бот создаёт её только в тот момент, когда Telegram отказался
переслать оригинал: он скачивает копию, отправляет её вам и сразу удаляет.
В обычном состоянии папка пустая или её вообще нет. Если бота прибили прямо
посреди отправки и копия осталась, её уберёт ночная очистка.

## Как это устроено внутри

Telegram разрешает подключить бота к личному аккаунту — это и есть режим секретаря. После подключения Telegram начинает сообщать боту о событиях в ваших личных чатах: пришло новое сообщение, его изменили, его удалили.

Бот запоминает приходящие сообщения: текст с разметкой, кто написал, когда, и номер файла, если файл был. Когда приходит событие об удалении или правке, он достаёт сохранённое и присылает вам.

Файлы, как описано выше, не скачиваются — бот просит Telegram переслать оригинал по номеру.
